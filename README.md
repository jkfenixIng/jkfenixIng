#### Las fronteras, primero

Monolito modular antes que microservicios por moda: un despliegue, módulos con contrato público y pruebas que verifican que esas fronteras siguen en pie. Si un módulo necesita leer las tablas de otro, el diseño está mal, no la librería.

</td>
<td width="50%" valign="top">

#### El contrato es el producto

Cuando otro equipo consume mi API, entrego contrato generado, catálogo de errores, ejemplos sacados de ejecuciones reales y trazabilidad de historias. Documentar el camino feliz no es documentar.

</td>
</tr>
<tr>
<td width="50%" valign="top">

#### Code-first y portable

El esquema sale del código y el modelo no queda casado con las particularidades de un proveedor gestionado. Cambiar de servicio debería ser editar configuración, no reescribir el dominio.

</td>
<td width="50%" valign="top">

#### Verificación antes que opinión

Percentiles y no promedios. Hallazgos con pasos de reproducción. Builds con las advertencias tratadas como errores. Si no lo medí, no lo sé.

</td>
</tr>
</table>
